# 知乎问答关系图谱 · 观点地图 Demo

把一维的回答列表，重排成一张能看见分歧的二维观点地图。

## 数据来源

Demo 支持两份语料，默认已切到**真实知乎数据**：

| 语料 | 性质 | 规模 |
|---|---|---|
| `data/corpus_live.json` | **真实** — 知乎开放平台搜索接口返回的社区内容摘要 | q1 47 条 / q2 38 条 |
| `data/corpus.json` | 演示 — 由公开聚合观点改写（无 API 时的兜底） | q1 24 条 / q2 16 条 |

真实数据通过官方 CLI 采集（`fetch_live.py`），9 个关键词覆盖同一议题的不同立场面，
按 `ContentID` 去重。身份属性取平台返回的 `AuthorBadgeText` 与 `AuthorityLevel`，
不做主观推断；赞数取 `VoteUpCount`，缺失时为 `null` 且不补全。

页面顶部徽章与详情面板底部声明会据实显示当前语料性质。

## 运行

渲染层是 TypeScript + Vite，数据层仍由 Python 流水线离线产出。

```bash
# 数据（离线，产出 data/graph.json）
python fetch_live.py                      # 采集真实知乎数据
python pipeline.py corpus_live.json       # 建图

# 网页（TypeScript）
cd web && npm install
npm run dev                               # 开发：http://127.0.0.1:5180
npm run build                             # 产出 web/dist
```

`data/graph.json` 需同步到 `web/public/data/graph.json`，网页运行时只读这份静态文件，**零 API 调用**。

## 算法要点

**质量分（与赞数解耦，是"被低估"功能的底座）**

\[
Q = 0.20\,\hat{L} + 0.34\,\hat{D} + 0.18\,S + 0.21\,V - 0.15\,E
\]

$\hat L$ 赞数对数归一、$D$ 信息密度（量化密度与专业密度分别归一后加权，
避免纯定性的深度分析被数字堆砌淹没）、$S$ 结构性、$V$ 亲历证据、$E$ 情绪化。

**被低估判定（接真实数据后修正）**：真实赞数呈重长尾（多数个位数），
原先的分位数判据会把近半内容误标。现用双重判据——$Q$ 进前 25% 且赞数 ≤ 本题中位数。
真实数据实测 47 条标 5 条、38 条标 7 条。

另外加了**赞数可用性检验**：搜索接口不保证提供真实赞数，当零赞占比 ≥35% 时
判定赞数不可信，自动关闭"被低估"识别并在界面如实说明，不伪装成有效结果。
当前两道题零赞占比 23% / 18%，判为可信。

**互为 kNN 建边**（防毛线团的关键）

\[
E=\{(i,j)\mid j\in \mathrm{kNN}_k(i)\wedge i\in \mathrm{kNN}_k(j)\wedge s_{ij}>\tau\},\quad k=4,\ \tau=0.18
\]

真实数据下边数自动稳定在 89–104 条（47/38 节点），未出现毛线团。

**场景维度：立场三分类的降级方案**

关键词立场三分类在"反驳式提及"（如"电池寿命焦虑被严重放大了"含负面词却是正方）、
条件句、政策陈述上准确率只有 15/20，即使加入句级反驳作用域判定也无法突破。

按方案避坑策略**把立场降级为带置信度的辅助标签**，改用 4 个可解释的场景维度作为布局主轴：

| 维度 | 正向 | 负向 |
|---|---|---|
| charge 充电条件 | 有私桩 | 依赖公共桩 |
| mileage 里程强度 | 高里程长途 | 低里程短途 |
| horizon 持有周期 | 长期持有 | 短期换车 |
| climate 气候友好 | 温暖地区 | 严寒衰减 |

这恰好命中真实分歧：这场争论本质不是"支持/反对"之争，而是**样本没对齐**——
有桩高里程的人和无桩严寒的人在描述不同的世界。

真实数据自动聚出的簇名印证了这一点：
q1 =「有私桩派·热泵/谷电」「严寒续航衰减·长途/增程」「短期换车看残值·保值率/二手」；
q2 =「高里程长途·网约车/电池包」「有私桩派·保费/谷电」「通用综合·维修/电池包」。

**争议边**：不能用"语义最不相似"找对立（低相似度通常只代表话题无关），
用维度反向距离 × 话题相关度：

\[
\mathrm{opp}(i,j)=\overline{|d_i-d_j|}_{\text{active}}\cdot s_{ij}^{0.3}
\]

## 视觉设计

**配色**：高级黑白杂志感，全站只有黑白灰，不出现任何彩色。浅色基底 `#fafaf9`，
深色基底 `#0c0a09`（非纯黑，带极淡暖灰辉光）。背景由三层叠加构成质感：
双焦点柔光渐变 + 56px 细网格（径向遮罩淡出）+ 程序生成的噪点层
（浅色 `multiply`、深色 `screen` 混合）。

**主题**：浅色 / 深色 / 跟随系统三态，分段控件带滑块过渡；选择持久化到
localStorage；跟随系统时监听 `prefers-color-scheme` 实时响应。
切换时注入全局过渡类，颜色平滑渐变；图表调色板从 CSS 变量重新解析后重绘。

**节点编码**：全部统一为圆点，只用大小与颜色区分维度，不使用菱形等异形。

| 通道 | 含义 |
|---|---|
| 大小 | 回答节点 15–45px 对应质量分 Q；概念节点按被引用数 |
| 颜色明度 | 身份：最深=权威 / 中灰=普通 / 次深=机构（同色系三级明度） |
| 描边 | 高质量低赞（被低估） |
| 位置 | 场景维度二维平面，簇间距离 = 场景差异 |
| 线型 | 实线=语义相似（粗细对应相似度），虚线=争议边 |
| 透明度 | 被滤镜排除降到 14%（不消失，保持空间记忆） |

**动效**：顶栏下滑入场、侧栏右滑、列表卡片阶梯淡入、节点入场扩散 +
被低估项涟漪脉冲、滤镜切换平滑过渡、抽屉侧滑、场景维度条宽度动画、
hover 邻接高亮与其余弱化、关闭按钮旋转。全部动效遵循
`prefers-reduced-motion`。

**刘看山**：左上角品牌图标用抠好的头部特写（浅色主题反相衬底提升辨识度）；
右下角常驻吉祥物，按交互切换素材包里的 6 个动作——待机、打招呼（载入/悬停）、
电脑（切题）、运球（点击/开启被低估滤镜）、晃悠（切主题）、瞌睡（42 秒无操作），
并配气泡提示。

## 工程取舍

- **布局预计算 + 固定随机种子**：`layout:'none'` + 碰撞松弛，演示每次打开形状一致。
- **`fitToView()` 两段式校正**：按"节点半径 + 标签占位"实测像素包围盒，先缩放后平移。
- **所有曲率归零**：曲线边会把弧线拱出包围盒造成裁切。
- **列表视图常驻**：与图谱共享滤镜状态，图谱是加速器而非阅读替代品。
- **原文可跳**：真实数据下节点详情提供知乎原文外链。

## 演示动线

搜索选题 → 地图展开 → 看簇名理解分歧轴 → 开「只看被低估」发现金边宝藏
→ 点争议边做正反对比 → 跳知乎原文。备了 2 道题，现场可主动切换一次。
